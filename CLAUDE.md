# Meteocadí — notes for Claude Code

Weather-station network site for Cadí-Moixeró / Berguedà. **All user-facing copy is in Catalan**, except the Spanish versions of the place and mountain pages (see below).

## Stack
- Canonical domain: `https://www.meteocadi.cat` (Vercel redirects the apex to www; Google indexes www). Use www in `site`, canonicals, JSON-LD and the sitemap.
- Astro (static output, `build.format: 'file'`, no trailing slash) deployed on Vercel. `vercel.json` sets framework/build/output, cron, redirects.
- Vercel functions live in `/api` (plain Node, not Astro). The Hobby plan allows at most 12 functions per deployment (a failed deployment would also stop the nightly archive from going live): there are 11 (Oct 2026). Shared code goes in files starting with `_` (not published as functions) and new endpoints go into an existing dynamic route when possible (as `/api/neu/mesurada` inside `api/neu/[estacio].js`). Functions: `ara.js` (all stations live, CDN-cached 15 min), `arxiva.js` (nightly archive → one commit to GitHub with `dades/YYYY/YYYY-MM-DD.json`, the month's `resum-YYYY-MM.json` and the hourly file `dades/YYYY/hores/YYYY-MM-DD.json`, via the Git Data API so each night is a single commit and a single build; max 60 s).
- Archive files: `dades/YYYY/YYYY-MM-DD.json` (one per day, every station; nightly since 2026-09-20). Days before that were recovered from each station's WU history (`v2/pws/history/daily`, 31 days per call, the station's whole life) and carry `"font": "historic"`; recovery started 5 Oct 2026 from the newest month backwards (state and next month in the session notes; done from the browser because the sandbox can't reach WU and the quota leaves ~300 spare calls a day). Hourly files (from 5 Oct 2026 on): per station, columns `h` (local hour), `tempAvg/High/Low`, `dewptAvg`, `humidityAvg`, `windspeedAvg`, `windgustHigh`, `winddirAvg` (vector mean), `rain` (mm in that hour), `pressure`, `solarRadiationHigh`, `uvHigh`, built from the 5-minute `history/all` readings.
- Rain counters: some consoles (La Pobla de Lillet, La Nou de Berguedà, Cerdanyola-Poble) reset their daily rain at UTC midnight (2:00 or 1:00 local), so until then the reading carries yesterday's total and the WU daily summary repeats it or misses the early-morning rain. `arxiva` recomputes the day's rain from the 5-minute readings (`dayRain`: increments only when the counter drops during the day) and keeps WU's value as `precipTotalWU`; `/api/ara` computes today's rain and the `rainDay` series the same way (`rainFromCounter`, from yesterday's last reading); the archive nulls a day whose rain equals the previous day's exactly (≥ 1 mm, `rainCarryOver`), the typical WU repeat in the recovered history.
- The old image generators (`/taula`, `/ranking`, `/previsio`) were removed; `vercel.json` redirects them to `/estudi`.

## Data
- Stations: single source of truth in `src/lib/stations.js` (Weather Underground IDs). Keep `api/arxiva.js` STATIONS_META in sync when adding a station.
- WU key limit: 1,500 calls/day and 30/min. Never call WU from the browser; go through `/api/ara` (cached).
- Archive read at build time by `src/lib/archive.js` (every nightly archive commit triggers a rebuild, so "yesterday" data is baked into HTML).
- Quality control of our stations (`src/lib/qc.js`, no list of broken stations to maintain: it is re-checked on every reading and every archived day, so a station comes back by itself once its data is good again):
  - physical limits for every value (WU sends -99/-9999-style "no data" values); isolated temperature spikes (> 5 °C away from both neighbours within 30 min) and per-reading highs/lows more than 6 °C from the reading's mean are ignored;
  - `/api/ara`: a station whose latest reading has no temperature, humidity or wind (outdoor sensors offline, only the console pressure left) gets `down: true` and `stale: true`, all outdoor values null, no series; the live table shows "Fora de servei" and the station page says so. Per sensor, `bad: ['rain' | 'wind' | 'temp']` with those values nulled: rain gauge not collecting (a station within 3 km and ±400 m got ≥ 4 mm and this one < 1/5 of it, or 0 mm while the network median is ≥ 5 mm), anemometer stuck (max gust 0 while the network median is ≥ 20 km/h), temperature more than 8 °C from stations within ±300 m (max/min: 10 °C);
  - impossible single-station values: rain ≥ 20 mm while every other station (at least 3) has less than a tenth and under 2 mm (`rainSpikes`: 251 mm at Coll de Pal with 0 elsewhere), and gusts ≥ 100 km/h with the day's mean wind under a twelfth of it and no other station above 45 % (`gustSpikes`: Pedraforca's anemometer gives 150–210 km/h on calm days; a real summit storm keeps a high mean wind); live and in the archive;
  - archive (`loadDays`): days without a valid max/min drop the station that day; the same rain and wind checks plus the spikes and the repeated rain null `precipTotal` / `windgustHigh` (`day.qc` lists `rain`, `wind`, `carry`), so records, history, episodes, the studio and the map never use them; `suspicious()` (cached per day) also flags max/min more than 10 °C from stations of similar altitude.
- Station watcher (`scripts/vigila.mjs`, GitHub Actions `.github/workflows/vigila.yml`, 5:20, 11:20 and 17:20 UTC, free on a public repo, no secrets: it uses the workflow's own token): reads `/api/ara` and yesterday's archive file and opens one issue per problem (station without data, `down`, no reading for 3 h, temperature/rain/wind flagged by the quality control, whole network down, archive file missing after 9 UTC), with an @mention of the repo owner so GitHub notifies him; it closes the issue by itself when the station works again (rain gauge and anemometer only count as fixed on a day with rain or wind). Issues are identified by `<!-- vigila:ID:kind -->` in the body. `DRY=1 node scripts/vigila.mjs` prints instead of touching GitHub.
- Colour scales (`src/lib/escales.js`: temperature, Meteocat rain classes, wind, humidity, `fieldColor`, `readableOn`) are shared by the maps (`camp.js` re-exports them) and the studio ranking (bars, dots and a scale legend like the map's).
- Home hero speaks to all of Catalonia ("El temps a Catalunya, de la vall al cim.", first button to the Catalonia map, second to the network); the hero card and the stations section are labelled as the Meteocadí network ("La xarxa Meteocadí, ara").
- Home: right after the hero, `CatalunyaAra.astro` (temperature map of Catalonia with as many station labels as fit without overlapping, hottest and coldest first and bigger; labels scale up on mobile; small meteocadi.cat mark; links to the public map).
- Home hero card: from 8:00 (Madrid) it shows today's extremes so far from `/api/ara` (live, refreshed every 15 min); before 8:00 or if the live data fails, the last archived day (baked in at build).
- Forecast: Open-Meteo (no key), client-side in `src/scripts/forecast.js`; build-time snapshot for SEO text in `src/lib/forecast-build.js` and `src/lib/weekend.js` (must never fail the build).

## Catalonia map (/mapa/catalunya)
- `api/xema.js`: all operating XEMA stations of the Meteocat from the Generalitat open data portal (Socrata datasets `yqwd-vj5e` stations, `nzvn-apee` semi-hourly readings; no key needed, optional `SOCRATA_APP_TOKEN`). Latest value per variable (last 3 h) plus today's max/min/rain/gust aggregates. CDN cache 15 min. Readings arrive ~45–75 min late; `data_lectura` is the UTC start of each 30-min slot. The portal sometimes fails for a while (JSON queries returning 500 "Internal error" on 5 Oct 2026, while the same query as CSV still answered): `get()` in `_xema.js` tries JSON, then the same query as `.csv` (`parseCsv`), then JSON once more. If everything fails, `/api/xema` and `/api/xema/24h` answer with the last good response of the instance (same day, under 3 h old) marked `stale: true`; otherwise `error: true` with no stations, cached 60 s. The map then draws no colour field (it would paint all Catalonia from our few stations), says Meteocat is not answering in a warning colour and retries every minute; with `stale` it says so next to the time. The studio note mentions `stale` too.
- `api/comarques.js`: ICGC comarca borders (dataset `aasi-gwnd`), simplified server-side, CDN cache 30 days.
- The page merges our stations from `/api/ara` (dark outline). Labels that collide become dots (priority: our stations, then the most extreme values). Snow depth only in season (sensors report a few cm of noise in summer).
- Always credit: Servei Meteorològic de Catalunya (XEMA) · dades obertes de la Generalitat; comarca borders: ICGC.
- Colour layer ("Mapa de color", every variable except snow): local inverse-distance interpolation on a 340×290 canvas clipped to the comarques — for each cell the 16 nearest stations, weight 1/(d²+2²)^1.25 (distance power 2.5) tapered by (1 − d²/R²)² with R = distance to the 17th station (modified Shepard: no seams when the neighbour set changes, no pull towards the Catalonia mean). Before Oct 2026 it was plain IDW power 3 with every station, which painted each station's colour up to half-way to its neighbours ("brotxa gruixuda"). Rain is interpolated as log(1 + mm) (`log: true` in `FIELD`), like its colour scale, so one very wet station doesn't spread its colour over drier neighbours. Temperatures are reduced to sea level with the lapse rate fitted on the same stations and then re-projected on the terrain height from `api/dem.js` (Copernicus DEM via Open-Meteo, 0.04° grid, CDN cache 1 year); without the DEM it falls back to the plain interpolation. Speed: ~110–140 ms for the whole grid (warm start with the previous cell's neighbours, latitude pre-filter). Wind and gust layers are labelled as only indicative. Colour scales (`TSTOP`, `RSTOP`, `WSTOP`, `HSTOP` in `camp.js`) are saturated with a clear hue change every 5 °C; rain uses Meteocat's accumulated-precipitation classes (0.1, 0.5, 1, 2, 5, 10, 20, 35, 50, 65, 80, 100, 150, 200 mm, same colours) as flat bands (`step: true`, no blending) and the legend lists every class. Class variables are painted at `HI` = 4 × the grid (`paintClasses`: bilinear value between grid points, classified per pixel against the class limits already in log space, mask `comarquesMask(geo, HI)`) and shown with `image-rendering: pixelated`, so band edges stay sharp when zooming instead of stair-stepped and blurred (~165 ms); the labels and the legend of both maps use the same scale (`fieldColor`), not `tempColor` (which stays for text on the dark panels of the rest of the site). The comarques' white fill is only drawn when the colour layer is off (it sits above the field and washed it out). The legend sits bottom right, over the sea, on desktop (bottom left it covered the Terres de l'Ebre) and below the map on mobile, with the swatches sharing the width. An "Intensitat" slider in the legend multiplies each variable's default opacity (0.25–1.6×, the map asks `computeField` for an opaque layer and sets the overlay opacity); remembered in the browser and applied to the downloaded image too.
- Period selector (under the variable buttons): "Avui" (since local midnight, default), "Darreres 24 h", "Un altre dia" (date input, 2010-01-01 to yesterday) and "Diversos dies" (two date inputs, up to 31 days, the last one may be today; shortcuts 3 / 7 / 30 days; default the last 7 days; a longer range is shortened from the start). The address carries `#24h`, `#AAAA-MM-DD` or `#AAAA-MM-DD..AAAA-MM-DD` so a day or an episode can be shared. For a range: rain is the total, max/min the extremes of the period, gust the highest; our stations come from the archive days plus today's `/api/ara` when the range reaches today, and drop out if a day is missing (a variable is left out if any day had it discarded). Rain classes adapt to the highest value on the map (`rainClasses` in `escales.js`, also used by the studio ranking legend): with big totals the low classes are dropped (from 50 mm the scale starts at 0.5, from 150 mm at 1, from 300 mm at 2; below that nothing is painted and labels are grey) and the legend goes up to the class just above the maximum (at least 20 mm), with extra purple classes 250, 300, 350, 400 and 500 mm (`RSTOP`). For a past day only Màxima, Mínima, Pluja and Ratxa màxima are enabled (the "now" variables have no value then); labels, legend, extremes, popups, image title and eyebrow follow the period (`legendOf`, `titleOf`, `per()`; image `eyebrow`/`suffix` in the snapshot).
  - XEMA: `api/_xema.js` (`xemaData(period)`, shared) behind `api/xema.js` (today) and `api/xema/[periode].js` (`24h` = the 48 half-hours ending at the newest reading; `AAAA-MM-DD` = local midnight to midnight, DST-safe via `midnightOf`; `AAAA-MM-DD..AAAA-MM-DD` = `xemaRange`, one aggregate query per day, 6 at a time, combined: a single query over the whole range takes the portal tens of seconds, one day ~0.6 s). `rinc: true` marks rain with too many missing readings (more than 2 h for one period, more than 10 % for a range); the map and the studio ranking leave it out of rain. Past days closed more than 6 h ago are cached 30 days at the CDN; the rest 15 min. Each station gets `inc: true` when more than 4 half-hourly temperature readings are missing in the period (count per variable in the same aggregate query); the map and the studio ranking leave those out of Màxima and Mínima, like our `susp` days. Unknown query keys (other than the `periode` Vercel may add) are redirected to the clean path, like `onlyCleanUrl`.
  - Our stations: today from `/api/ara`; 24 h computed from the `/api/ara` 15-min series (`last24`: WU rain is cumulative since midnight, so increments are summed and a drop means a new day) and only when the series reaches back to the window start, otherwise just the current values; past days from the archive via `archiveFor()` (`/estudi-dades.json` and, for older dates, the year file; stations flagged `susp` are skipped). Period labels add the year when it is not the current one.
- Mouse wheel / trackpad zoom: on, but it only takes over the wheel after the pointer has really moved over the map (250 ms) or after a click, and it is released when the pointer leaves the map; a page scroll cancels the pending wake-up, so scrolling down the page with the cursor resting where the map passes does not zoom. Ctrl/Cmd + wheel (and trackpad pinch) always zooms the map, never the page.
- Outside Catalonia nothing is shown: a mask polygon (world minus `src/lib/catalunya-contorn.json`, the union of the comarques, static) covers the basemap. The page CSS lifts the global `svg { max-width }` for Leaflet panes, otherwise the mask SVG collapses to 0 px.
- Two versions of the same component (`src/components/CatalunyaMapa.astro`): the public `/mapa/catalunya` (every variable and station mode, but no download at all: the image code is not in its bundle, tiled `meteocadi.cat` watermark between the colour layer and the labels, fixed to the viewport, plus a mark top left; no context menu, hidden when printing; screenshots cannot be blocked in a browser, the watermark is the protection) and the internal `/estudi/mapa` (`internal`: no watermark, exposes `window.__cmap.snapshot()` and the page adds the download buttons and the preview dialog).
- Station selector (top right): "Selecció" (default: labels that would overlap are hidden, so zooming in shows more), all (overlapping ones as dots), "Capitals" (nearest station with data to each comarca capital, ≤ 20 km, list `CAPITALS`) or none (colour only). The downloaded image follows the same mode.
- On mobile (≤ 640 px) the station selector goes above the map and the legend below it (out of the map, so they cover nothing); on wider screens they are map corners (`corner()` moves them on resize).
- The downloaded image follows the zoom: if the web map doesn't show all of Catalonia, the image shows the same area at the same scale (`view` in the snapshot, "cover" framing in a rounded window, labels only if they fit inside, legend below the window).
- Download (only in `/estudi/mapa`): `src/scripts/mapa-imatge.js` (lazy-loaded) draws a 1080×1350 post, a 1080×1920 story or a 1600×900 horizontal image (X, webs; text and legend on the left) on canvas from the same state (variable, station mode, colour layer): only Catalonia, labels decluttered at image scale, legend in the sea corner, data credits (XEMA licence requires them) and meteocadi.cat. Preview dialog with Download and, where the browser supports it, Share.
- Bagà Nord and Bagà Sud are hidden on this map (`HIDDEN_HERE`) so the three Bagà stations don't pile up; Bagà Centre stays.

## Radar (estudi, intern)
- `/estudi/radar` (`src/pages/estudi/radar.astro` + `src/scripts/radar.js`): internal only (noindex, robots, out of the sitemap, not linked from the public site). Not for monetised pages: Meteocat's legal notice asks for a licence to reuse protected content; ask them before using the radar publicly.
- Radar: Meteocat's own map tiles (`static-m.meteo.cat/tiles/radar|plujaneu/YYYY/MM/DD/HH/mm/07/000/000/xxx/000/000/yyy.png`, TMS rows, zoom 7 ≈ 1 km, one image every 6 min, the newest ~6–12 min late). The 3 × 3 tiles over Catalonia are composed in a canvas, each pixel is matched to Meteocat's 19-level scale and repainted with the chosen scale (`radar-pal.js`: Meteocat's own, the default, or the Meteocadí one, which starts in blue and is less fluorescent), shown as one georeferenced canvas with crisp pixels when zooming. Background: Esri World Hillshade relief without roads (default), OpenTopoMap or none. If the server stops allowing pixel reads (CORS) or the colours no longer match the scale, the images are shown as they come and the download is disabled. 2-hour animation, opacity (default 1, fully opaque), rain/snow product.
- Stations (default: today's rain): XEMA + our network, `rain1h` (last hour with data: the two newest half-hour readings; for our stations, from the 15-min series), today's rain, gust, temperature. Zeros are dimmed.
- Wind and convergence lines are hidden for now (Oct 2026, Oriol wasn't convinced): `const WIND = false` in `src/pages/estudi/radar.astro` leaves out the controls, keys and credit, and `radar.js` only loads `/api/vent` when the controls exist. `api/vent.js` and the key stay in place; set `WIND = true` to bring it all back.
- Wind: `api/vent.js` asks Météo-France's WCS (0.025°, Licence Ouverte 2.0) for U/V at 10 m over the radar area (GeoTIFF, read with `geotiff`). First AROME-PI (`aromepi/1.0`, MF-NWP-HIGHRES-AROMEPI-0025-FRANCE-WCS: a run every hour, a forecast every 15 min up to 6 h) for the current quarter of an hour (now − 5 min, like the radar): mean wind if the API offers it, otherwise the 15-min gust components (`kind: 'gust'`, same direction); budget 12 s / 6 requests, a 401/403 (no AROME-PI subscription) goes straight to the fallback. Fallback: AROME (`arome/1.0`, run every 3 h, hourly forecast). Response has `model`, `kind`, `step` (15 or 60), and when it fell back, `tried` with the AROME-PI statuses. CDN 5 min (AROME-PI) or 15 min (AROME); the page asks again every 5 min. Needs `METEOFRANCE_API_KEY` (portail-api.meteofrance.fr, APIs "AROME" and "AROME-PI"; the key only covers the APIs subscribed when it was generated, key valid until 3 Oct 2027); without it the page says so. Arrows on a screen grid; convergence lines = the axis (ridge) of −divergence above an adaptive threshold (≥ 2·10⁻⁴ s⁻¹), chained and smoothed. Observed wind arrows come out of each station.
- Image: `renderRadarImage` in `mapa-imatge.js` (same formats; map always in a window with the legend below, radar under the labels and arrows, credits for Meteocat, Météo-France and XEMA).

## Meteocadí Neu (/neu, under construction)
- The new ski product that will replace `/esqui` (plan: publish around mid-November 2026, then `/esqui` redirects to it). It looks like a site of its own inside the domain: own layout `src/layouts/NeuLayout.astro` (`Base` with `bare`: dark header with the "Meteocadí Neu" brand and, on desktop, the menu; mountain-ridge edge; own footer with the data credits; on phones a bottom tab bar Avui / Estacions / Mapa / Allaus) and own styles `src/styles/neu.css` (mobile first, a 760 px column on desktop; snow colour scale shared by bars, tables and the map). Hidden until launch: `noindex`, `Disallow: /neu` in `robots.txt` and out of the sitemap (`HIDDEN` in `astro.config.mjs`); remove the three at launch.

- Resorts: `src/lib/neu/estacions.js` (`NEU`, from `places.js` places with `ski`, minus Rasos de Peguera, which has not run its lifts for years): display name without "Estació de", short name for the map, zone, country, alpine/nordic, official slope-status page (`ESTAT`, only links for now), avalanche bulletin of the zone (`allausOf`: ICGC, Centre de Lauegi d'Aran, meteo.ad, Météo-France), nearest resorts, SCT road radius (Catalonia only). Still missing: the French resorts, Sant Joan de l'Erm, Virós-Vallferrera and Naturland (add their facts from official sources first).
- Data, always through our functions with CDN cache (Open-Meteo's free tier is non-commercial, 10,000 calls a day):
  - `/api/neu` (`api/neu.js`, logic in `src/lib/neu/fonts.js`, `previsio`): one Open-Meteo call for every resort, top and base, 7 days plus the 5 before (`mountainUrl`/`parseMountain`), CDN 1 h; on failure the instance's last good answer (< 6 h, `stale: true`), otherwise `error: true`.
  - `/api/neu/<estació>` (`api/neu/[estacio].js`, `horaria`): hour by hour, today and tomorrow, top and base (temperature, precipitation, snow, code, wind, gust, direction, visibility, freezing level), CDN 1 h; unknown slug 404, extra query keys 308 to the clean path.
  - `/api/neu/mesurada` (`api/_neu-mesurada.js`, `neuMesurada`): XEMA snow depth (variable 38, `nzvn-apee`) of the stations at ≥ 1,000 m over the last 5 days: depth now (median of 5 readings against spikes, < 3 cm = 0, only if the last reading is < 6 h old), change in 24 h and new snow per day (the day's maximum minus the depth at the start of the day, days with ≥ 12 readings). CDN 30 min. Uses the Socrata helpers exported by `api/_xema.js`.
  - At build time the pages are painted with one shared Open-Meteo call (`src/lib/neu/build.js`, never fails the build); the browser repaints with the three APIs every 30 min. Measured snow and hour by hour are browser only.
- Shared logic and HTML (build and browser): `src/lib/neu/neu.js` (reuses `rateDay` and `dayVerdict` of `ski.js`): the day's headline (`parte`), best day to ski, where it will snow most, measured-snow pick, map pins, station list for a chosen day, resort profile with the 0 °C isotherm and the snow line (`profileSVG`), the four header figures (`factsHTML`), verdict of the chosen day, 7-day strip, past and coming snow (`trioHTML`, `snowChartSVG`; past days measured at the nearest sensor or, without one, the model's estimate), snow type (in season), hour by hour 8–18 h every 2 h (from 17 h, tomorrow), 7-day table and its note, nearby sensors (≤ 35 km, at most 300 m under the resort base). Catalan details: "d'11 km/h", "a la 1:05", units glued with non-breaking spaces.
- Pages: `/neu` (`src/pages/neu/index.astro`): headline, best day / most snow / measured snow cards, Leaflet map (pins: a dot at the resort and a label beside it, numbers first and names where they fit; layers "Neu prevista" today / 3 / 7 days and "Gruix mesurat" at the sensors), "Quin dia i on" (day chips, zone select, list sorted by the day's rating, 6 shown then "Veure les N estacions"), avalanche bulletins. `/neu/<estació>` (`src/pages/neu/[estacio].astro`): profile and figures, chosen day (tap a day of the strip), anchor tabs, snow, hour by hour, 7 days, measured snow nearby, avalanches, roads (`/api/transit?near=`), official links, resort facts, nearest resorts.

## Navigation
Top menu: El temps (/temps), Mapa (/mapa/catalunya), Estacions, Muntanya, plus the Esquí and Contacte buttons. Radar, Historial, Sobre el projecte and the network map (/mapa) are linked from the home (Explora section), the stations page and the footer.

## Episodes (automatic reports)
- `src/lib/episodes.js` scans the daily archive at build time for heavy rain, strong wind, heat, cold and the first valley frost of the autumn (thresholds in `LLINDARS`; another station must corroborate). Consecutive days merge into one episode; slug `/episodis/YYYY-MM-DD-type` (start date, stable while the episode grows).
- Measured data only, never forecasts; never claim snow amounts (gauges don't measure snow).
- `/episodis` is noindex and left out of the sitemap while there are no episodes (see `astro.config.mjs`). The home shows a strip for an episode that ended ≤ 6 days before the last archived day; month pages list their episodes.
- With the recovered history there are dozens of episodes: `/episodis` groups them by year (heading linked to the year page), and year pages list theirs. Strong wind was raised to 120 km/h at high stations and 70 km/h in the valley (Oct 2026): summit gusts over 100 km/h are routine in winter.
- Station pages: records since the station started (value and full date), "El clima a … mes a mes" (means of complete months, per calendar month, with each month's extremes and how many years), "Any per any" (links to the year pages) and the last 31 days. Place pages show the same records (max, min, gust, wettest day).
- Test with fake data: `DADES_DIR=<dir> npm run build` (overrides the `dades/` folder read by `archive.js`).

## Spanish pages (/es/)

## Road status (Servei Català de Trànsit, open data)
- Places with `roads` (and optional `cameras`) in `places.js` show `RoadStatus` (tunnel, Coll de Pal).
- `api/transit.js` reads the SCT incidents GML feed (updated hourly) and filters by road and km range: `/api/transit?roads=C-16:110-135,BV-4024`. CDN cache 10 min.
- `api/camera.js` proxies SCT camera images (their server is http only). Only IDs in its `ALLOWED` set are served; add new cameras there too. A camera that fails (SCT placeholder or error → 404/502) is hidden on the page. Oct 2026: c1649 (Berga) and c1661 (Guardiola) were returning 404.

## Security
- The GitHub repo is public: never commit keys or tokens (`.env*` is ignored). Secrets live in Vercel env vars: `WU_API_KEY`, `GITHUB_TOKEN` (fine-grained, this repo only, Contents read/write), `CRON_SECRET`, optional `SOCRATA_APP_TOKEN`, `CONTACT_EMAIL`. The old WU key is still in the code as a fallback (and in the git history): once a new key is set in `WU_API_KEY`, delete the old one at Weather Underground and remove the fallback from `api/ara.js` and `api/arxiva.js`.
- Pending (Oct 2026): Vercel only had `METEOFRANCE_API_KEY` and `GITHUB_TOKEN`, so the site still runs on the WU key written in the code and `/api/arxiva` has no `CRON_SECRET`. Order: new WU key → `WU_API_KEY` in Vercel → remove the fallback from `api/ara.js` and `api/arxiva.js` → delete the old key at WU; add `CRON_SECRET`; replace `GITHUB_TOKEN` with a fine-grained token (this repo, Contents read/write).
- `/api/arxiva` only runs with `Authorization: Bearer $CRON_SECRET` (or, without the variable, only for the Vercel cron, `x-vercel-cron-schedule` header). Never log tokens.
- Functions without parameters (`ara`, `xema`, `comarques`, `dem`) redirect any query string to the clean URL (`api/_net.js`), so nobody can skip the CDN cache and burn the source quotas; `ara` also keeps its last good answer for 5 min in the instance.
- Text from third parties that ends up in `innerHTML` must be escaped or cleaned (`RoadStatus` escapes; `api/xema.js` strips `< > "` from names).
- `vercel.json` sets nosniff, Referrer-Policy, X-Frame-Options / `frame-ancestors 'self'` (no one can frame the site), Permissions-Policy. No full script CSP yet (inline scripts, tiles, fonts, Meteocat radar iframe).
- `/estudi` and `/estudi/mapa` are hidden (noindex, robots) but not password-protected.
